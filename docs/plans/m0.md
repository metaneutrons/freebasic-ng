# M0 — Foundation, identity and trust

M0 establishes FreeBASIC-NG as a maintainable, independently releasable fork.
It contains no public compiler release and no deletion of legacy build paths.

## Decisions

| Topic | Decision |
| --- | --- |
| Product name | FreeBASIC-NG |
| Repository and package identity | `freebasic-ng` |
| Compiler executable | `fbc` |
| Upstream version line | 1.20.0 |
| Release tag prefix | `freebasic-ng-v` |
| AUR packages | `freebasic-ng` and `freebasic-ng-bin` |
| Native Tier 1 target set | Linux x86_64/aarch64, macOS x86_64/arm64, Windows x86_64/arm64 |
| Amiga-family status | Separate experimental target-SDK preview until validated |

## Exit criteria

1. The upstream base, identity and licence boundaries are documented in the
   repository and match GitHub metadata.
2. `version.mk`, CMake and Release Please agree on 1.20.0.
3. GitHub Issues and milestone tracking are enabled; the M0–M5 roadmap is
   represented by linked Epic and implementation issues.
4. `main` is the protected default branch. CI has read-only default permissions,
   immutable Action references and dependency update automation.
5. A protected `release` environment exists. Publication credentials are scoped
   by channel and are not committed or stored as repository-wide secrets.
6. The M0 CMake bootstrap defaults to bundled generated sources, and the CI
   build and smoke tests pass on its declared hosts.
7. Legacy paths have an inventory and removal criteria; none is removed merely
   because it is old.

## Deferred work

M1 implements the reproducible multi-host build and pre-release artifacts. M2
implements Debian, Homebrew and the two AUR packages. M3 validates Amiga-family
target SDKs. M4 publishes the website and stable release. M5 removes legacy
paths only after their replacements are proven.

The channel-specific environment contract is documented in
[release-security.md](../release-security.md).

The M5 removal gates are recorded in
[legacy-inventory.md](legacy-inventory.md).
